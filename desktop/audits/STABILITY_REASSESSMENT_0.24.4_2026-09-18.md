# 交易驾驶舱 0.24.4 稳定性再审

日期：2026-09-18。范围：本地最近已验收的 0.24.4 构建、其源码归档，以及单独标注的未发布工作区改动。未确认用户当前实际运行的安装版本。

后续开发整改与验证见 [未发布整改记录](STABILITY_FOLLOWUP_2026-09-18.md)；本报告保留原始审计时点的发现，不把后续源码修复倒写为0.24.4安装包已有能力。

## 结论

当前架构适合继续使用和收敛，不宜推倒重建。最重要的剩余问题不是页面数量，而是：取得的数据是否完整进入复盘、数字的含义是否在模块之间保持一致，以及长期留档是否可恢复。

“可用研究终端”不等于“完整收益核算系统”或“每日必定留档的无人值守系统”。没有证据表明本次发现已经造成真实账户金额错误或数据损失。

## 检查边界

- 本轮不修改应用逻辑、不重新打包、不安装、不触及真实业务数据；仅新增本报告。
- 未调用真实券商或模型，未读取凭证；复现使用内存数据、隔离测试及源码检查。
- 0.24.4 发布清单记录 15 项门禁通过，包含单元、源 UI、包内 UI、依赖与源码对照。此前记录为 955 项单元/契约测试通过；它不代表真实多日验收。
- 本轮当前开发工作区全量测试为 999 项，995 通过、4 失败：一项揭示下述单位语义漏洞；一项新测试的未知原因码预期需修正；一项新测试揭示 EMA 成熟度口径冲突；旧会话等待测试在并发运行中 8 秒超时，单独重跑约 5 秒通过。最后一项属于测试时序敏感，不能据此断言产品再次丢失结果。
- 当前工作区已有未发布的容量、分段存储、对账与评估改动，版本号仍为 0.24.4。不能把这些改动当作已验收安装包能力，也不应直接覆盖同版本产物。

## 一、优先修复：有代码或隔离复现证据的问题

### 1. 复盘取数会制造本可避免的“证据不足”

- **已复现：8 个股票标的会挤掉 QQQ。** 基准被追加在股票之后，再统一截取前 8 个；8 股输入实际只请求这 8 股，QQQ 出现在遗漏清单。应为基准独立保留名额，股票分批或明确覆盖范围。
- **已复现：一个慢源丢弃其他已返回行情。** 总超时与全部请求完成竞速；超时时没有保留已完成结果。A 立即返回有效行情、QQQ 悬挂，最终两者都被标为超时。应逐源保存成功结果，只终止未完成请求。

定位：[标的上限](/Users/gawei1995/Documents/stock_agent/desktop/src/review/review-cycle-outcome-metrics.mjs:91)、[超时回收](/Users/gawei1995/Documents/stock_agent/desktop/src/review/review-cycle-outcome-metrics.mjs:175)。该文件与 0.24.4 清单哈希一致。

### 2. 复盘上下文保留了金额，却丢失部分解释金额的证据

- 快照清洗未保留完整估值方法、FX、质量、账户来源与完整性信息；持仓最多取 200 项，没有同步输出遗漏数量。
- 复盘直接跳过组合分析使用的“来源字段→实际发送内容”核验。现有分片哈希、时间边界检查仍有价值，但不能替代原始字段覆盖核验。
- 应传递精简但自足的来源包：账户范围、观察/估值时间、币种与换算、质量限制、输入/投递/遗漏计数、原始记录引用。详细证据按需读取，不靠把全部 JSON 塞入提示词解决。

定位：[快照清洗](/Users/gawei1995/Documents/stock_agent/desktop/src/review/review-cycle-analysis.mjs:1009)、[投递校验分支](/Users/gawei1995/Documents/stock_agent/desktop/src/engine/codex-workspace.mjs:3802)。对应模块与 0.24.4 一致。

### 3. 数值“校验通过”尚不能保证完整语义正确

- **已复现：百分比分母不匹配仍通过。** 仓位事实的单位类型和数值正确、分母却为股价收益，仍得到 verified。
- **已复现：价格的币种和标的不匹配仍通过。** HKD/0700.HK 参考价引用 USD/AAPL.US 收盘事实，审计未拒绝。
- **已复现：未知集中度变为零。** 两个持仓权重都未知时，逐项权重仍是 null，但最大持仓占比变成 0。应返回未知，或明确为已知子集下界。
- **事实标签不自足：期权权利金市值被称为毛名义价值。** 2 张 × USD 5 × 100 = USD 1,000 的乘数运算正确，但该金额不是 Delta 风险或标的名义敞口。风险层有衍生品不完整提示，单项数值事实仍可能被截取为完整风险指标。
- **EMA 质量口径冲突。** 技术层按三倍周期评估成熟度，数值事实层却将短于 144 的 EMA 直接视为成熟。30 根日线的 EMA21 可得到相互矛盾的成熟度/置信度标签；不是 EMA 算术已被证明算错。
- **展示单位问题。** 收益率相减所得 QQQ 超额应表示百分点；目前与普通收益率都显示为 %。

处理：按指标校验单位类型、分母、币种、标的、时点与来源引用；每个事实自己携带限制。区分权利金市值、标的名义额与 Delta 敞口，缺失不补零。统一成熟度规则，区分百分比与百分点。整篇自然语言尚未逐数核验，不能用结构化字段通过来代表报告全部数字可靠。

定位：[单位审计](/Users/gawei1995/Documents/stock_agent/desktop/src/engine/numeric-claim-audit.mjs:399)、[未知集中度](/Users/gawei1995/Documents/stock_agent/desktop/main.mjs:4398)、[期权事实](/Users/gawei1995/Documents/stock_agent/desktop/src/engine/numeric-evidence-adapter.mjs:86)、[EMA 事实](/Users/gawei1995/Documents/stock_agent/desktop/src/engine/technical-numeric-evidence.mjs:112)、[超额展示](/Users/gawei1995/Documents/stock_agent/desktop/renderer/review.js:1441)。相关模块/函数已与 0.24.4 清单、包内内容或归档核对。

### 4. 历史搜索的“没找到”不一定可信

长回复缓存只保留前 12,000 字符；缓存刷新主要比较时间，没有记录正文截断状态。隔离探针将关键词放在回复后半段，搜索返回空且 partial=false。应保存全文完整性；缓存不完整且未命中时定向回查，或明确说明仅搜索了部分内容。

定位：[正文裁切](/Users/gawei1995/Documents/stock_agent/desktop/src/engine/codex-workspace.mjs:6651)、[缓存刷新判断](/Users/gawei1995/Documents/stock_agent/desktop/src/engine/codex-workspace.mjs:6807)。对应文件与 0.24.4 一致。这不同于聊天正文被删除。

### 5. 月度查询辅助接口把所有月末写成 31 日

## 三、冗余建设、历史遗留与 UI 收敛

1. **旧流程不是全部还在双写。** 旧案例只读、显式迁移和旧规则写入口退役已经完成，不应再次当作未修缺陷。保留兼容阅读必要，但停止为旧对象新增功能。
2. **网页原型已经退出默认生产入口。** 继续冻结为设计参考，不再平行维护第二套功能。根 README 仍有旧案例直接改订单、“评估器尚未接入”、固定 16:00 等陈旧描述，应统一链接当前能力说明。
3. **控制逻辑仍过度集中。** main、Codex 适配、主 UI、复盘 UI 共约 2.2 万行。它不是现成事故证据，但状态交叉与回归成本高。按账户同步、快照、会话终态、证据投递、复盘工作流逐块拆分；不要再建第二套 Agent 运行时。
4. **重启会丢失尚未提交的 UI 草稿。** 现有草稿保存在内存，跨刷新有效，不等于加密持久草稿。可增加明确保存/恢复草稿，不能用明文浏览器存储金融笔记。
5. **大周期缺少渐进分析路径。** 超过 96,000 字符/128 块会拒绝发送，这是有效保护。体验上应提供范围预览、建议分组、分段分析与总复盘；不能通过默默截断放行。
6. **健康状态要翻译成行动。** 页面优先回答“这次用了什么、缺什么、是否影响结论、下一步怎么办”；原始错误与证据 ID 放详情，避免让用户自己理解内部状态名。

## 四、应该固定下来、不再反复改动的边界

- 原生 TradingView 是用户看盘主界面，不另做图表替代品。
- 只保留一个 Codex 运行时；宿主负责身份、上下文、结果持久化和 UI，不另建并行工具执行系统。
- 券商查询只读；研究能力自由不等于真实交易写操作授权，也不声称通用研究环境是绝对交易沙箱。
- 确定性数据与计算由宿主负责；模型负责解释、情景和研究判断。EMA/Fib 是证据选项，不是唯一策略。
- 数值必须绑定来源、时点、币种/单位/分母与可用性；未知不等于零，事后信息不冒充事前判断。
- 每个异步结果归属明确的账户、授权代际、请求、会话和证据版本；新旧结果不得相互覆盖。
- 复盘固定为周期→证据版本→AI 分析→验证草案→用户确认→前向样本→再评估；旧记录留可追溯引用，不复制成新独立样本。
- 只有真实终态且结果已核验持久化，才显示正式完成；已有暂存文本应可读，但不能假冒最终结果。
- 每次发布绑定唯一版本、源码/依赖/Skill 指纹及验收清单。当前未发布工作不得复用稳定包的“已验证”身份。

## 建议推进顺序

1. **先消除会误导判断的问题：** 复盘取数回收、基准遗漏、复盘来源字段投递、单位/未知值/期权/EMA 质量语义、历史搜索完整性和月末辅助接口。
2. **再补长期使用闭环：** 容量与分段备份恢复、逐项收益对账、真实多日采集验收。新分段未完成备份恢复前不得启用。
3. **最后做维护与交互收敛：** 加密草稿、渐进式大周期复盘、状态文案、旧文档收敛、按职责拆分控制模块。

本报告不是新版本完成声明。未发布模块、真实运行验收和跨设备恢复仍各自保留未完成状态。
