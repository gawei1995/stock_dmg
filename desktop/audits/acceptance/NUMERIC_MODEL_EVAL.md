# 模型数值理解：固定离线评估集 v1

状态：**语料已建立，模型尚未运行，未产生模型通过率。** 此处只补原 A→B→C 计划中的固定评估交付，不修改 0.24.6 运行代码或引入第二套 Agent harness。

[12 个合成题及独立答案](numeric-model-cases.json) 覆盖换汇/仓位分母、负现金/未知、期权乘数与敞口、部分卖出毛盈亏、百分数/百分点、部分日终证据、胜率分母、缓存和冲突、未完成 K 线/EMA、Fib 锚点公式、近似成本分布和前后信息。每题包含可投递输入、标准数值、必要限定语与逐项评分标准。没有真实账户或实时行情。

本集按 OpenAI Docs 的指导，将目标、样例和具体评分条件分开，并保留人工复核；不以流畅度或整体观感判断正确性。[官方评估指导](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

## 怎样使用

1. 用户确认模型运行安排后，再使用现有 Codex 链路；本交付没有自动调用入口，不选择模型、不创建会话、不访问凭证。
2. 每题独立、无其他题目上下文。仅投递 `prepareCase(suite, caseId).payload`；**绝不能把整个题库、expected 或 checks 给被测模型**。答案与评分标准只交给评审者。
3. 使用无工具的封闭证据条件；若模型能读取包含标准答案的工作区、使用历史答案或外部资料，该次结果无效。仅要求“不读取”不足以代替实际工具隔离。若现有入口无法保证，不称正式对比测验。
4. 记录下列运行信息与原始回答；不要让被测模型给自己打分。评审逐条读取自然语言与数字，不能靠关键词出现判断及格；计算、来源或限定语互相矛盾时对应项失败。
5. 评分每项为 pass / fail / not_assessed。每题全部项通过才通过；任一关键项失败即阻止验收。缺答和未审题保留在总分母，不因平均分高忽略致命错误。
6. `summarizeManualChecks` 仅统计人工录入的 true/false/null，不验证原始回答是否正确；`answersVerifiedByScript=false` 必须保留。测试里的全 true 是计数器自测，**不是模型答题结果**。

首次运行建议作为校准集，人工核对评分标准歧义。后续至少重复运行并报告每题差异，而非单次通过宣称稳定；新增题目或改答案须升级语料版本，保留旧结果。这个小型合成集不是生产分布、投资业绩或“所有模型数字已核验”的证明，也不决定股票买卖。

时间冲突题刻意混入晚于截止时间的证据，用于检验模型能否识别并排除；即使答对，也不证明生产盲审在传输层没有接触未来数据，后者由独立上下文与时间防火墙回归验证。期权题的原始入场损失与当前市值风险、唯一样本ID与统计独立性，均须分口径评价。

## 每次运行应留存的信息

| 字段 | 要求 |
| --- | --- |
| 状态 | not_run / incomplete / complete；完成不等于通过 |
| 环境 | App 输入 hash、运行时版本、实际模型标识及推理设置、Skill 指纹 |
| 语料 | suite id、题库文件 hash、每题 payload hash；禁止把答案发送给模型 |
| 权限 | 工具实际禁用状态；若无法隔离或访问答案则 invalid |
| 回答 | 会话/轮次标识、时间、原始完整输出及 SHA-256；缺答保留 |
| 评分 | 评审者、每项 pass/fail/not_assessed、引用回答片段、失败原因、争议项 |
| 汇总 | 完成数/总题数、每项分母、关键失败、重复运行波动；不只报平均分 |

当前所有模型运行、回答和人工评分字段均未生成。离线检查命令为 `node --test desktop/audits/acceptance/numeric-model-cases.test.mjs`，它只校验语料结构、独立算术、答案隔离和计数规则，不调用模型。
