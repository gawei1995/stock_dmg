## 隔离和失败判定

主程序通过 Inspector 在首个模块执行前暂停；驱动断言 `Break on start / 0:0`、冻结包内 `encrypted-store.mjs` 的完整路径和源哈希、`app.isPackaged`、版本及独立 userData/sessionData。随后才安装外部边界拦截并恢复启动。独立复审也核对了首次暂停位置和已知启动调用路径。

每次启动均实际拦截三次 Codex 子进程启动意图、一次 TradingView 请求以及登录项设置调用。Node/Chromium 的已知出站入口及外部应用调用被阻止；设置无效本地代理，未触发真实模型/券商。**这属于已知入口插桩和代理隔离，不是操作系统级防火墙或网络流量审计。**

驱动对连接、调用、启动及退出设定截止时间；只终止自己启动的进程。前几次驱动开发失败是暂停态求值、Promise 保留与退出表达式问题，不作为产品缺陷。主动拦截导致的 Agent 失败日志也不是本次产品回归。

## 不在本次结论内

- 长桥、IBKR/TWS/MCP、真实 Codex 或模型的端到端兼容、耗时和数值引用质量。
- 原有真实 profile 的升级、授权保持、TV 登录保持或大历史迁移。
- 真实连续交易日 EOD 捕获、休眠/断网后的实际覆盖。
- 钥匙串拒绝/损坏、物理断电、任意尚未完成写入的退出安全，或容量上限压力。

本次证明的是已经等待保存成功的复盘记录可跨正常退出和独立进程重启持久化。发布清单和源码归档保持原样；此验收记录及驱动是在归档之后添加，不声称它们已经包含在原源码压缩包中。完整进度见 [实施台账](../STABILITY_IMPLEMENTATION.md)。
