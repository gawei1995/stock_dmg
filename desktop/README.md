# 交易驾驶舱 Desktop

## 0.24.6：证据传递、数值语义与历史留档

- 复盘基准独立保留 QQQ 名额，超时只终止未完成的数据源，不丢掉已成功返回的行情。快照来源、估值、汇率、质量和遗漏数量进入证据包，并独立核验源到实际投递的一致性。
- 数值引用核对单位、分母、币种和标的；未知不补零，期权权利金市值不称为标的名义敞口，EMA 成熟度口径一致，收益率之差显示百分点。固定样例不是实际模型全文逐数验收。
- 周期结果增加十项收益证据核对，绑定账户、周期、证据版本和原件哈希；盲态不接收事后对账。当前仍缺完整资金流、费用、税费等原件，不计算正式账户收益。
- 本机恢复包区域可手动预览并确认整理组合快照或雷达历史。旧记录保存在不可变加密分段中，跨段查询和原校验链不变；不会自动归档或删除历史。归档作用于该账本全部账户，按追加顺序保留活动记录。
- 归档前及实际密文提交时均核验完整备份容量，期间暂停其他业务写入；取消不改记录，提交后复核失败保持暂停并提示重启检查。v4 恢复包包含五类根文件及全部引用分段，兼容 v2/v3；仍限原本机钥匙串身份。
- 历史搜索可查长回复全文并返回命中附近节选，分页完成与日期范围完整分列；无日期记录不能被略过后宣称完整。月份查询正确处理短月与闰年。
- 归档前建议导出同机恢复包。旧 0.24.4 不认识分段根格式；启用归档后不要用旧版直接打开同一数据目录。源码回退不等于数据格式可无损降级。
- 发布验收以独立 0.24.6 清单为准；0.24.5 为未交付的中间构建，复审后继续修正技术预取和两处含义标签，不作为推荐安装版。真实券商/模型、连续交易日和 4 GiB 上限压力验收仍未完成，不自动安装或改变真实账户。

## 0.24.4：收盘采集边界与本机恢复

- 已保存当前账户/交易日的收盘快照后，断连轮询也先核验本地记录，不再次重连；提前收盘日的日 K 完成判断与采集窗口共用交易日历。受控宿主测试覆盖跨日、睡眠、重启、断网、换号和提交失败；不代表真实连续多日在线已验收。
- 应用内对话索引、最近结果、观察计划与 TV 页面地址移入独立加密业务文件。首次启动成功迁移后，以新文件为准；旧副本保留作恢复材料但不自动回流。账户权威元数据、后台/登录启动偏好和凭证仍由本机管理。
- 同机恢复包增加业务索引文件；不包含 Codex 外部完整对话、TV 登录状态或布局。旧四文件包保留当前应用索引。恢复明确展示覆盖、删除与保留，阻止恢复期间账户变化和旧缓存写回；提交后重启失败或回滚未完成时保持写入冻结并明确报错。
- 系统状态独立展示六类存储；容量只知道条数、不知道字节时标为部分核验。完整容量管理、分段封存与收益对账仍属后续工作。

## 0.24.3：复盘主路径收敛与系统状态

- 新财报复盘直接从所选真实订单和确认事件建立轻量周期；日期或盘前/盘后精度保留为日期信息，不编造精确财报时刻，也不成为事前封存。
- 历史财报案例保留只读。先预览来源、订单范围与限制，再确认迁移；原记录、封存、旧结果引用和原对话保留。迁移幂等，旧结果不冒充新分析；之后可在新周期重选订单并保存新记录。
- 验证中心是唯一的新验证写入口。旧规则页深链导向这里，旧独立测试/规则写接口停用；新版本通过单次原子提交建立。来源失效、重复血缘样本及未完成分析不会误算为新前向样本。
- 顶部「系统状态」只读取本机已有事实，展示连接、数据时间、存储、收盘覆盖、Agent 证据/完成状态、能力和容量边界。打开时暂时隐藏原生 TV 视图，关闭返回原工作区；不触发券商同步或模型分析。未测量的账本字节数不伪装为零。
- 发布验收继续绑定源码/依赖/Skill，新增源与包内健康弹窗交互检查；验证结果以本版发布清单为准。连续多日运行、跨设备灾备与完整收益对账仍不在本批完成声明内。

## 0.24.2：可靠性收敛第一批

- 保存采用先加密写入、同步临时文件，再原子提交的方式；失败保留内存和磁盘的上一版本。钥匙串暂不可用或解密失败会明确停止，不自动创建空工作区；界面显示各业务存储的降级状态。
- 历史订单与财报查询贯穿账户、授权和连接代际守卫；相同范围可以合流，不同范围提示尚未查询。切换账户保留各自历史缓存，时间分片重叠查询并按稳定 ID 去重。
- 一条 final 消息不代表整轮结束。远端仍运行时继续接收，不能因静默 5 秒强制完成或中断；传输失败或正文分页不完整显示可恢复的暂存文本，不生成正式结果或计划。历史读取共享总时间预算。
- 全组合分析显式收到技术雷达摘要与卡片，交付清单核验应投递字段；双券商保留逐来源汇率、日期和告警，不把缓存升级为实时。
- 连接、持仓、历史、雷达与快照的状态分别维护。自动快照更新局部覆盖状态；复盘只读取一次全量摘要，订单分页独立；读取不锁住返回 TV，验证表单草稿按账户与协议版本隔离保留。
- 启动及判定历史缺口前先核对已持久快照；索引写入失败不能把真实采集误报成缺失。读写未成功则停止缺口判定，既有终态冲突明确报告，不静默改写。
- 每轮记录实际请求 Skill 的内容指纹及前后变化；已有自定义版不覆盖，与内置版不同会提示兼容状态未核验。指纹不保存 Skill 正文，也不宣称覆盖目录外依赖。
- `npm run verify:release -- --target mac` 统一验证源代码与打包 UI、生产依赖、运行模块和产物；验证清单记录 dirty 工作区输入，不把旧提交号冒充新发布源码。

该批次没有改变 EMA/Fib 策略、150% 毛敞口上限、IBKR 研究/计仓边界或 partial 快照的收益资格。旧复盘主路径收敛、长期采集与灾备仍按[实施台账](audits/STABILITY_IMPLEMENTATION.md)推进；不包含 Developer ID 签名或 Apple 公证。

左栏共用持仓表，通过「全部账户 / 长桥 / IBKR」切换；支持独立刷新与按券商展开。同市场股票可合并敞口，期权独立展示报价和 Greeks，购买力不跨账户相加。首次连接与权限说明见 [IBKR_SETUP.md](./IBKR_SETUP.md)。

## 产品结构

```text
┌────────────────────┬──────────────────────────────────┬────────────────────────┐
│ 长桥真实账户        │ TradingView 个人网页会话          │ 交易 Agent              │
│ USD净资产/现金/仓位 │ Layout/画线/私有指标/Watchlist    │ Codex + 综合证据/风险计划 │
└────────────────────┴──────────────────────────────────┴────────────────────────┘
```

中间区域不是 TradingView Widget，也不使用应用自绘行情。它是 Electron `WebContentsView` 直接加载的 TradingView 完整网页，并使用独立持久会话。

## 安全架构

### TradingView

- 远程视图启用 `sandbox`、`contextIsolation` 和 `webSecurity`。
- 禁用 Node integration、preload、插件、`webview` 与实验特性。
- 主导航仅允许 TradingView HTTPS 域名。
- 不向 TradingView 注入脚本，不抓取页面 DOM，不共享 Chrome Cookie。
- Cookie/localStorage/cache 只存在 `persist:tradingview` 分区。

### Longbridge

- MCP 与 OAuth 全部运行在 Electron main process。
- OAuth 使用 PKCE、`127.0.0.1` 临时端口回调、随机 state 和 public-client 模式。
- OAuth 精确申请 `scope 6`（账户/持仓读取）与 `scope 10`（订单/成交历史查询），拒绝包含 `scope 11` 的授权 URL；旧 scope 6 凭证通过版本化授权档案触发一次显式升级。
- Token、持仓缓存与观察计划使用 `safeStorage` 加密保存；没有明文回退。
- Renderer 只能调用窄化的“连接、刷新、运行 Agent”IPC，不暴露通用 `callTool`。
- 全球服务端 `/v2` 与只读查询白名单共同阻止订单写入；历史委托、历史成交、当日委托与当日成交仅供复盘关联，`option_quote` 只用于期权报价与真实合约乘数。Bearer Token 只允许发往官方 `.com` 的 HTTPS `/v2` 端点。

### Agent

- Codex App Server 是唯一的 Agent harness：它统一管理持久线程、历史、工具生命周期、Skills/MCP/Apps、流式事件、取消与结果收集。长桥、EMA/Fib 与风险计算只是同一 harness 的只读证据能力，不是第二个规则式 Agent。
- 右栏支持新建和直接打开多个独立 Codex 会话。每个会话使用自己的持久 `thread`；`thread/resume` 后显示原 transcript，下一次 `turn/start` 继续同一上下文。项目规则、Skills/MCP/Apps 共享，但对话上下文不会混在一起。应用只允许切换本机加密 registry 中登记的驾驶舱线程。
- 新会话先显示“新对话”，首个真实问题会在本地立即生成简洁摘要标题并同步到 App Server；不再用日期时间命名，也不会把驾驶舱内部提示词写成标题。
- 单个 App Server/RPC 连接按 `threadId` 管理多轮运行；不同会话可以并发，同一会话仍保持一轮一轮执行。每条会话拥有独立 spinner、流式文本、工具事件、取消和终态回收，不维护第二套 harness。
- 分析范围分为三类：`position` 读取选中真实持仓，`candidate` 可分析未持有代码并形成候选买入条件，`portfolio` 一次检查全部持仓与组合健康。
- 上下文按范围分层：单标的只注入目标和组合聚合摘要；只有全组合分析才注入完整持仓。稳定规则来自项目/Skills，实时数量、成本、价格、汇率、指标和权重来自本轮最新证据。
- 候选 scope 会把 Top1/Top5、主题暴露、现金、购买力、毛净暴露、保证金、组合告警与最多 260 根紧凑 OHLCV 注入 Codex。Codex 使用叙事/技术 Skills、开放技术证据栈与可用只读 MCP 独立提出 Stage、失效依据、仓位和 `cash_only` / `margin_within_cap` / `disabled` 决策；不再有本地 Stage 1 或 2%/4% 建议。价格/成交量、相对强弱、筹码或成本结构、AVWAP、波动率/期权、板块同行和事件反应均可参与；EMA/Fib 只是可选基础证据。应用复算模型引用的真实 bar/EMA/Fib，并执行两分钟新鲜度、估值、购买力、集中度、风险预算、保证金与衍生品覆盖的硬边界。组合 gross exposure 在 120% 进入预警，150%（1.5×）为不可突破的硬上限；融资必须由 Codex 显式选择且由宿主裁剪，界面区分模型原始建议与宿主接受值。
- EMA、OHLCV、自动 Fib 与账户权重由本地确定性引擎计算；自动 Fib 仅为 `AUTO / ADVISORY`。最终 Fib 选择和建议仓位由 LLM 判断，宿主不从 Markdown 猜数字，只接受结构化且通过校验的结果。
- 核心账户、行情、风险与技术数值使用 `Numeric Evidence v1`：每项都带 `factId`、明确单位、有效时间、来源、输入引用、计算公式、完整性与稳定哈希。真实 0 与未知值严格分离；百分比统一为 `percent_point`。EMA、自动 Fib、14/28 日成本集中代理、相对 QQQ 超额收益以及宿主核验后的 AVWAP 都进入同一数值契约；代理/自动锚点固定携带低置信度与无仓位权限标记。候选分析把 `model_proposal` 与本地硬边界产生的 `host_decision` 分开保存，模型建议不会冒充最终有效仓位。
- 候选仓位必须同时提交持有周期和独立压力情景。技术失效距离只形成 planned risk；gap、事件、流动性或工具最大损失形成 stress risk。宿主以两者较大值核算风险预算，并在模型返回后再次刷新账户与行情；刷新失败时保留研究文字但有效新增仓位归零。
- 日线技术证据使用已确认收盘的 OHLCV，发布 1/3/5/10/20 日收益、CLV、TR/前置 ATR14、gap、20 日相对量、10/20 日方向效率和相对 QQQ 的同日期超额收益。数据护照显示来源、端点、最新/应有交易日、缓存年龄、输入哈希及能力矩阵；持久缓存只能做研究，不能直接授权仓位。
- 每次长桥同步都会生成带稳定哈希的 `Portfolio Valuation Gate`：账户同步时间、每个持仓的报价时间与交易时段、期权类型/乘数、原币市值和 USD 汇总、账户净资产勾稽分别验收。`freshForSizing` 必须同时满足“两分钟内账户快照 + gate schema/hash 有效 + gate outcome pass”；账户刚同步不会替某只旧报价“续期”。闭市时最近官方完成交易日的 mark 可按市场日历通过，缺失、未来时间、活跃时段过期报价或勾稽失败会保留研究能力但关闭仓位数值与计划保存。
- 左侧“技术雷达”把真实持仓与自选合并为最多 50 个标的，持仓优先，QQQ 只读取一次，并发上限 4。它按一个精确已完成日线 cutoff 批量计算 EMA3/5/8/13/21/144/169、1/3/5/10/20 日路径、QQQ 同日超额、周线与 14/28 日成本集中代理，缺失值保持 N/A，不前向填充。结果写入独立加密 hash-chain 账本；正式 EOD 组合快照确认后自动尝试更新一次，也可手动扫描。全组合 Agent 直接消费最近批次，不再逐只联网等待；变化/异常排名仅用于观察分流，不是买卖信号。
- 技术证据分为两层：Tier-A 是上述批量、确定性、仅观测的雷达；Tier-B 才是单标的或候选的深度证据。两层都只接纳已完成的 bar；同一批次的标的、QQQ 和已配置行业都必须对齐到同一个精确 cutoff，任一标的缺该日即为 N/A，绝不以前一日数据前向填补。Tier-A 不选 AVWAP 锚点、不读取期权或催化剂，也不生成交易信号。
- 叙事结论使用本机已登录的 Codex App Server；线程为持久会话，应用重启后通过 `thread/resume` 延续。
- Codex 项目目录默认是 `~/Documents/stock_agent/trading-agent-workspace`，可用 `TRADING_COCKPIT_CODEX_WORKSPACE` 覆盖为其他绝对路径。
- 不再使用 `--ephemeral`、`--ignore-user-config`、广泛工具黑名单或 45 秒分析截止；正常继承本机 Codex 配置、项目规则、Skills、MCP 与可访问 Apps。普通分析保持自然 Markdown；候选 scope 仅用窄化输出 Schema 同时取得 Markdown 与可验证仓位复核。券商 MCP 按服务身份和交易写能力进行防护，涵盖已识别长桥、IBKR 及命名可识别的下单、改单、撤单、行权和转账工具；Apps SDK 另保留破坏性动作开关。研究 shell、文件及一般查询工具不由此禁用：这是券商工具层防护，不是整个 Agent 的通用只读沙箱，也不能替代券商端只读授权。
- Codex 可以使用网页、Shell、文件、Skills、MCP、Apps 与其他已配置工具；采用 `danger-full-access` 工作区能力和 Codex 原生自动审批审查。
- 应用先用 `config/read` 保留用户原有 `disabled_tools`，再通过 `thread/start` / `thread/resume` 的 `config` 并入 Longbridge 下单、改单、撤单、平仓、行权和 DCA 写工具；查询工具不受影响。同一配置将 `apps._default.destructive_enabled` 设为 `false`，不会额外拉一轮 App 清单拖慢启动。线程能力清单校验失败或仍暴露上述交易写工具时，模型 turn 会 fail closed。
- 选中持仓或候选目标、组合聚合风险和已验证指标通过 App Server `additionalContext` 注入；全组合 scope 才包含完整持仓。不会发送账户号、OAuth Token 或长桥凭证。
- 输入框支持 `/` 分析命令、`$Skill`/`$App` 和 `@MCP/tool` 实时联想；Skill 与 App 会转换为 App Server 原生结构化引用。
- Agent 正文和工具事件实时流式显示；取消使用 `turn/interrupt`，不会销毁持久线程。
- 右栏默认只突出 Codex 结论，确定性证据和风险卡片折叠显示；Markdown 使用暗色语义渲染，长输出在栏内独立滚动。标准 Markdown 来源链接、裸 HTTPS 与 Google 安全跳转会显示为暗色主题链接；点击后只经主进程二次校验并交给系统浏览器，不允许远程页面接管驾驶舱导航。
- 工具开始/完成事件按 App Server `itemId` 合并；Agent 消息也按 `itemId` 分流，`commentary` 只作运行预览，最终正文只聚合 `phase=final_answer` 的完整 item。通知是低延迟路径，同时每 5 秒按 active turn ID 轻量读取 `thread/turns/list(itemsView=summary)` 对账；发现终态后再单次读取持久 item 历史，按 turn 顺序去重并合并所有 final 段。
- 不把首个 `final_answer` 当作整轮唯一结果，也不按固定静默时长完成或中断 turn。正常收口以 `turn/completed` 为准；若终态通知丢失，从持久历史回收。远端明确仍运行就继续接收；无法核验终态或历史不完整时仅展示可恢复的暂存正文，保留原对话入口，不生成正式结果和交易计划。
- 最终消息通过事件、原 IPC、前端周期恢复和持久 turn 历史四条幂等路径返回；UI 从任务提交后即主动对账，不再依赖先收到某个 final 事件。持久历史的 terminal 状态优先于陈旧 active 标记；完成结果不会被下一条中断 turn 覆盖。UI 完成信号不等待加密写盘；每个 Codex 会话的最近结果仍分别加密保存，重载或切换后只恢复对应结果。
- Skills、MCP 与 App 能力清单使用 single-flight 与 10 分钟缓存；会话新建、切换和结果恢复不会重复枚举整套 MCP Schema。能力变化通知带 30 秒冷却，避免连接器重试触发清单自激循环和 App Server 高 CPU/内存占用。
- “本机对话”列表只读取 thread 元数据并在 renderer 本地筛选；点击后对目标 thread 执行一次 resume，并由 `initialTurnsPage` 顺带取最近 30 个摘要 turn。若 App Server 水合超时，界面使用加密本地索引立即打开，不会因对话数量增加而扫描全部正文。Agent 的显式历史查询仍由最近 30 天加密索引与动态工具提供。
- 归档按最后活动时间而不是创建时间判断；持续使用超过 30 天的会话不会被错误轮换。超过窗口且无活动的驾驶舱线程会原生归档、可恢复但不在 UI/工具结果中显示。
- 驾驶舱对话是本机 Codex App Server thread，不会同步成 `chatgpt-conversation://`，因此不会显示在 ChatGPT/GPT 网页聊天历史中。
- 模型尚未返回文本时每 15 秒更新一次已运行时长，界面不会把上游等待伪装成“卡死”，并始终允许取消。
- 当持久线程剩余模型上下文低于 2% 时自动请求 Codex 压缩，以保留关键历史继续工作。
- 技术数据不足时进入 `DEGRADED`，隐藏不可靠计划字段。
- 运行 Agent 时复用两分钟内的真实长桥快照；快照较旧时最多前台等待长桥 1.5 秒，随后用已有真实快照继续并把刷新转入后台。463、超时或断线只降低证据置信度，不再阻塞 Codex 最终答案；账户、汇率与持仓请求并行，日线使用两分钟缓存。
- 期权缺少 OPRA 或真实合约乘数时仍显示真实数量，但市值/权重明确降级；即使权利金市值可估，缺少标的映射、Delta/Greeks 与标的等价名义汇总时，也不会套用正股线性风险估算，候选仓位与杠杆会 fail closed。
- 证据链只展示数据源、参数、时间、记录数与状态，不展示内部思维链。
- 保存计划只会写入本地加密观察记录。
- 持久会话意味着每轮选中持仓证据与分析结果会进入本机 Codex rollout，并用于模型请求；线程记录仍由本机 `CODEX_HOME` 管理。

### 复盘实验室

- 独立于 TradingView/Agent 主视图。“复盘周期”支持订单生成的单标的交易区间、催化剂、持仓生命周期与月度组合四种模式；原财报案例和独立旧测试/规则只读保留，新分析仅运行周期协议，验证与人工决策统一在验证中心，聊天结论不会直接升级成规则。
- 默认轻量入口先记录三段用户原话，再原子建立周期和关联证据：事后回忆不能冒充事前判断，本次感悟不回填旧计划，未来预判只从保存时间起生效。选月份会按 `America/New_York` 自然月扫描账户历史，但主证据只纳入真实成交及已成交/部分成交父订单；未成交、取消、拒绝、过期、等待中订单与不可核验成交只作排除审计。单标的交易区间只由当前框选的 Buy / Sell 订单或成交定义，绝不向前搜索历史首笔。选订单会展开该单已归档成交；直选某笔成交时父订单仅作补充证据，兄弟成交不扩展窗口。它固定标为 retrospective；月度严谨预判则可在零订单时提前建立，继续使用时间防火墙。
- 已有案例或轻量周期支持重新增删订单。新的关联保存为递增 evidence revision，旧集合与旧复盘保留但标记为 stale；trade_window 会随新订单集合原子重算真实活动区间，避免漏选较早买单或较晚卖单时被旧范围卡住。
- 周期事前快照包含我的判断、市场预期、条件动作、失效位，以及当时可得的基本面/技术面证据。封存版本带时间戳、知识截止时间、哈希和 ex-ante/partial/retrospective 资格；封存后不可覆盖原版本。
- 阶段一为盲态复盘：初始计划与每个不可变检查点分别形成节点证据胶囊，订单、成交、基本面和技术日线必须严格早于该节点自己的知识截止时间；阶段二必须等待周期结束并拥有与当前封存版本、节点时间线及证据哈希匹配的阶段一结果。首次分析分别创建新的持久 Codex 对话并以 `cycle_id` 配对；同一复盘内的后续追问继续使用原对话。
- 可调用长桥 `history_orders` / `history_executions`，并合并 `today_orders` / `today_executions`。历史默认范围 180 天、最长两年；兼容通用 `has_more` 与美区 `us_page/us_limit + total_count` 两套分页。自动关联按周期的标的和时间范围筛选；部分成交后取消仍进入交易事实，纯撤单、挂单、拒单、过期和不可核验记录只保留为 `audit_only`，不进入 Agent、路径或验证样本。
- 孤立股票 execution 会先按唯一父订单 ID 使用只读 `order_detail` 做有界回补；仍无法核验父订单、方向与币种时保留 reported price 与排除原因供审计，但主价格显示为“成交价未核验”且不进入宿主 P&L。低价期权权利金与能够匹配父订单的低价股票成交仍正常保留。
- 单标的筛选会立即读取最近最多 3 次财报的本机缓存，并后台刷新过去 240 天的候选日期。框选交易的价格路径按交易所时区计算：从最早选中 Buy 成交到最晚选中 Sell 成交，最多 3 个交易日逐日展示，跨度更长按 `3 / 3 / … / 余数` 分段；部分卖出保留未退出数量。结果阶段在可计算时由宿主核验已关联成交配对毛利、周期/基准/超额收益和日线价格 MAE/MFE，无法计算时保留 `null + reason`。
- 复盘页维护独立的加密只追加组合快照账本，保存版本化常规收盘重估、成交后观察与手动观察；应用运行时每 15 分钟检查一次，并在系统唤醒或解锁后立即补检。正式捕获只允许在美股官方常规或提前收盘后 `+10` 至 `+240` 分钟的闭区间内进行；过点先封存 `gap`，绝不使用后来账户状态补造历史。窗口内若长桥因网络短断而离线，系统只在已有授权时做无交互重连，传输失败按 `1/2/4/8/15` 分钟有界退避；认证或权限失败会停止当天剩余自动尝试。每个美股交易日最多一个 v2 常规收盘重估：证券按官方常规时段最后成交 mark 重估并记录行情时间和估值版本；成功后后续轮询只做本地幂等核验，不再重估或联网覆盖。被动盘后 mark 不会自动保存或覆盖重估，只有手动或成交后观察会另行追加。连续性账本按交易日记录 `attempting / confirmed / degraded / gap`，界面显示最近 45 个交易日的确认率和明确缺口，不会把应用关机期间的空白伪装成历史。持仓数量与现金来自收盘后抓取，因此该重估固定为 `partial`、不能作为确定性收益端点，也不冒充完整券商收盘净值。旧 EOD 保留但不阻止新版重估，窗口内失败会重试。关闭应用期间不会补造漏掉的历史快照。当前组合和周期历史端点严格分列。QQQ 与持仓日线使用独立加密缓存。缺少真实月初/月末快照、费用、税费、外部资金流或足够行情时只做降级复盘，不回填历史、不把净资产端点变化冒充周期收益。
- “无人值守采集”默认关闭，必须在复盘页由你显式开启；开启后才允许关闭最后一个窗口时保留后台采集，并登记 macOS 登录后隐藏启动。关闭该开关会同时取消登录启动，但不会删除既有加密快照或缺口事实。系统只在监控开启后的权威美股交易日、常规或提前收盘加四小时重试窗口结束后，才把没有确认快照的日期记为 `gap` 并通知；它不会把任何旧空白、盘后状态或后来账户数据伪造成当日收盘。设备关机、休眠或长桥断连期间依然可能漏采，缺口会明确保留给复盘，而不是静默回填。
- 组合快照不会按天自动删除；活动区上限为 12,000 条或 64 MiB，达到上限拒绝新增而不裁剪历史。可在本机恢复包区域明确预览、确认后，将旧记录整理到不可变加密分段，完整历史仍可查询。系统状态显示活动/历史条数和密文容量；这不是无限容量或恒定内存方案。
- 技术雷达使用另一份加密 hash-chain 账本，活动区上限为 400 个批次或 96 MiB；同样可显式整理历史分段，不自动滚动删除。查询目前重建完整历史；恢复包保护上限为 4 GiB、2048 文件、单文件 128 MiB，未做上限规模压力验收。
- 技术复盘样本严格区分历史校准与前向样本：历史校准只用于发现与描述，不能进入正式统计或自动升级规则；当前门槛先要求至少 20 个唯一周期的合资格前向样本并经人工复核。重叠持有窗口、同一事件拆分成多个周期等统计独立性尚未建模，因此正式评估器与规则晋级继续 fail closed，不能把“唯一周期”误称为“独立样本”。`planned R`（事前失效距离）、`stress R`（跳空/事件/流动性等压力情景）和宿主核验的 `realized R` 是三个独立字段；不会由收益、PnL、MAE/MFE 或当前持仓反推或互相替代。
- “受信任加密备份”v4 复制五类本机 `safeStorage` 密文业务状态及其全部引用历史分段：复盘工作区、市场历史、组合快照账本、技术雷达账本及应用内业务索引，并附 SHA-256 完整性校验与账户范围核验。未引用孤段不冒充历史，也不自动清理。业务索引包括对话指针、最近结果、观察计划和 TV 页面地址，不等于 Codex 外部完整对话备份。它不包含 `secure-state.bin`，不导出 OAuth token、PKCE/注册材料、Codex 登录凭证、设备后台开关或账户权威元数据；恢复保留本机设置。恢复只能在可解密原文件的同一 macOS Keychain / Electron `safeStorage` 身份下进行，不能作为跨设备迁移。兼容旧 v2/v3，旧 v2 四文件包未定义应用索引槽位，恢复时保留当前索引；其他显式缺失的旧槽位仍按确认清单删除，旧迁移副本不得自动回流。进程内失败回滚不等于多文件物理断电事务。
- Agent 结果可携带结构化验证草案；界面主路径收敛为“AI 草案 → 用户确认开始观察 → 后续复盘候选 → 用户确认纳入 → 自动汇总指标 → 达标后人工决策”。候选由主进程生成并标记前向、跨边界或历史校准，来源周期仅作基线；观察可停止并归档，活动列表移除但审计历史不删除。草案绑定产生它的复盘运行和证据版本，重复确认不会复制；重选订单或重写三段记录会把旧草案、协议和规则冻结为历史。确定性协议评估器已接入，但人工净 R、历史校准和不满足点时/前向资格的样本不能推进正式门槛；界面按当前证据解释未就绪原因，不承诺所有复盘都能晋级。

### 汇率与组合基准

- 组合默认统一按 USD 估值并计算仓位权重。
- 账户净资产、总现金和购买力直接请求长桥的 USD 口径；不会把同一账户的 HKD/USD 展示值相加，也不会对账户总额做第二次换算。
- 优先读取长桥账户汇率；长桥汇率工具不可用时，自动查询 ECB 最新每日参考汇率。
- 长桥 MCP 与 ECB 的原始汇率方向先分别适配成统一的 `from → to` 内部语义；USD/HKD 会做方向与数量级校验，异常时降级而不是继续计算权重。
- ECB 参考汇率保留来源与观察日期，并最多缓存 7 天；它只用于估值和权重，不代表券商可成交汇价。
- 左侧真实持仓与右侧 Agent 可独立隐藏；两条分隔线可拖拽或用键盘调整宽度并持久保存。右侧结论区域独立上下滚动，输入框固定在底部。

## 数据状态

- `SYNCED`：最近两分钟内从 Longbridge MCP 完成同步；只有逐标的报价与估值 gate 同时通过才可参与仓位评估。
- `STALE`：真实快照已超过两分钟或本轮刷新失败；可继续研究，不可输出有效新增仓位。
- `CACHED`：上一次真实 Longbridge 快照的本机加密缓存。
- `DEGRADED`：真实账户与数量仍可用，但存在未定价持仓、缺失报价时间、技术行情不足或请求失败。
- `REAUTH_REQUIRED`：OAuth 已过期，需要用户重新授权。
- `SCOPE_UPGRADE_REQUIRED`：旧授权缺少订单/成交历史查询；确认后清理旧本地凭证、重新进行只读 OAuth，并自动重试原同步范围一次。
- 账户快照时间与持仓报价时间分别展示；快照新鲜不等于每个市场的报价正在交易，界面会显示最早到最新的 mark 时间范围。

应用不会使用生产演示持仓。未连接时显示空状态；测试目录中的合成数据只用于验证计算函数。

## Agent 连接设置

- Agent 栏顶部的“连接设置”默认折叠。按用户确认，新版在没有已保存偏好时默认“跟随系统代理（实验性）”；已保存的“沿用启动环境”不会被覆盖。
- 系统代理通过本应用启动的 Codex 原生 `respect_system_proxy` 功能启用。启动前核验所选运行时的功能支持；不支持、无法核验或超时时明确停止 Agent 启动，不静默改为直连。它不会修改系统代理或全局 Codex 配置，也不会向全部工具子进程注入代理环境变量。
- 可在界面切回“沿用启动环境”。保存只在下次启动整个应用后生效；当前对话、模型和工具授权不变，也不会为应用设置而终止任务。界面分开显示本次启动模式与待生效选择。
- 当前本机运行时把此功能标为 `under development`，故保留实验性提示。网络配置已应用不等于已完成连通测试；PAC、代理例外、外部 MCP 及所有工具网络路径没有被一并保证。具体错误仍按实际请求反馈。

## 当前限制

- TradingView 登录状态属于 Electron 独立会话，不会复用浏览器或 TradingView Desktop 的登录状态。
- 左侧持仓与右侧 Agent 可独立收起，也可分别拖拽到合适宽度；中间 TradingView 永远保留最小可视宽度，调整只改变原生 `WebContentsView` 边界，不缩放或拉伸图表。布局偏好仅保存在本机。
