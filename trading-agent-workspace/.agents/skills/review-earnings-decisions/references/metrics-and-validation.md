## 1. 口径原则

- 将一个 `标的 × 财报事件 × 决策包` 视为一个独立观察；同一事件的拆单不是多个胜负样本。
- 在看结果前指定主要观察窗口、胜负条件、基准和计划风险。敏感性窗口不得替代主要窗口。
- 同时报样本数 `N`、指标覆盖数 `N_valid` 和覆盖率。缺失值不按 0 处理。
- 费用、税费、借券成本、期权价差和 FX 可得时使用净结果；否则明确标为毛结果。
- 对同一宏观冲击或同一标的的重复事件考虑相关性；不要把相关样本当作完全独立。

## 2. 收益与路径

设计划初始风险金额为 `planned_risk`：

```text
net_R = net_pnl / planned_risk
win_rate = count(net_R > 0) / N_valid
payoff_ratio = abs(mean(win_R) / mean(loss_R))
expectancy_R = win_rate * mean(win_R) + (1 - win_rate) * mean(loss_R)
profit_factor = sum(positive_net_R) / abs(sum(negative_net_R))
capture_efficiency = realized_gain / MFE_value
```

- `planned_risk` 必须来自事件前已保存的仓位、失效位或最大权利金风险。缺失时 `net_R` 不可计算。
- 同时报平均值与中位数，避免单个跳空交易主导赔率。
- `MAE` 和 `MFE` 从统一起点到主要窗口计算。多次加减仓时优先使用逐日持仓加权 P&L 路径；只能用价格路径时注明近似。
- 报告最大亏损、下行分位数或 Expected Shortfall（样本足够时），不要只报均值。

## 3. 执行与风险

建议把计划动作拆成可核验项，不合成一个主观总分：

```text
action_adherence = 已按计划完成的可核验动作数 / 到期应执行动作数
risk_deviation = (actual_peak_risk - planned_risk) / planned_risk
invalidation_latency = 首次确认失效后的风险降低时间 - 首次确认失效时间
fill_slippage = 实际成交价 - 预先记录的执行基准价
```

- 失效从未触发时不计算失效延迟。
- 失效条件含糊、事后改写或无法从可得数据确认时，将其标为不可核验。
- 对取消/未成交订单同时评价“意图是否符合计划”和“实际风险是否建立”，不可混为一项。
- 期权仓位按最大损失、Delta/名义敞口和波动率暴露中可得的口径报告，不要只按合约市值。

## 4. 组合与对标

```text
peak_gross_exposure = max(sum(abs(position_market_value)) / NAV)
peak_net_exposure = max(abs(sum(signed_position_market_value)) / NAV)
benchmark_excess = strategy_return - preselected_benchmark_return
```

- 使用事件窗口内的真实账户/持仓快照；只有当前持仓时不得反推历史峰值。
- 基准需在事前或统一研究方案中选择，例如标的、行业 ETF 或 QQQ，避免结果出来后挑最弱基准。
- 机会成本只对事前存在的合格替代方案或已记录未交易信号计算；不能事后挑选上涨最多的股票。
- 同时报等权事件结果和资金加权结果，防止大仓位掩盖低命中流程或小仓位放大样本数量。

如事前保存了上涨/中性/下跌情景概率，可计算 Brier Score 或分箱校准；没有概率记录时不得补写并声称预测准确。

## 5. 样本和规则晋级

规则状态只允许按顺序推进：

| 状态 | 最低要求 | 能否指导真实仓位 |
|---|---|---|
| 候选 | 至少一个可解释案例，写成可证伪假设 | 否 |
| 已登记测试 | 冻结纳入规则、主指标、窗口、失效与排除条件 | 否 |
| 待人工 review | 完成预定样本或观察期，披露全部排除与缺失 | 否 |
| 试行 | 人工批准；通常至少 20 个相对独立、已核验样本，净期望为正且尾部可接受 | 仅限受控小规模 |
| 已验证 | 人工批准；通常至少 50 个已核验样本，含两个以上环境及未参与修改规则的留出集，成本后净期望仍为正 | 在既定风险边界内 |

20/50 是最低审计门槛，不是统计充分性的保证。若事件稀少、分布重尾、样本高度相关或效果很小，应提高样本要求或延长观察期。任何指标不得自动提升规则；人工 review 必须记录批准人、时间、版本和理由。

必要时用 bootstrap 或贝叶斯区间报告期望与胜率的不确定性。区间跨过无效阈值时，结论保持“不确定”，不要以点估计晋级。

## 6. 防过拟合检查

每轮 review 回答：

1. 纳入规则是否在看结果前确定？所有排除是否留痕？
2. 是否只报告最佳窗口、最佳标的或最佳市场环境？
3. 规则修改后是否重新开始测试版本，而非继续累计旧样本？
4. 是否有未参与发现和调参的时间顺序留出集？
5. 是否扣除费用、滑点、FX 和无法成交的影响？
6. 是否同时保留亏损案例、未交易信号与连接失败的样本？
7. 是否把市场 beta、事件跳空或单一异常值误认成可重复 edge？
8. 失效规则是否能在真实交易时点被观察并执行？

任一关键问题回答“否”时，将结果标为探索性或降级，不得用更复杂指标掩盖证据缺口。
