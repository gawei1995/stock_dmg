# 证据与输出约定

## 目录

1. 复盘单元
2. 证据层
3. 完整性检查
4. 输出结构

## 1. 复盘单元

以 `symbol × earnings_event_id × decision_package` 为基础样本。一个决策包可包含事件前建仓、加仓、减仓、期权保护、事件后调整和平仓，但必须由用户明确选择或确认关联。

季度通盘复盘先冻结纳入规则，例如：

> 纳入本财报季中，被用户标为“依据财报操作”、且事件前 20 至事件后 10 个交易日内存在实际成交的全部决策包。

保留符合规则但没有下单的候选信号，才能评估选择偏差与机会成本；若系统没有记录未交易信号，明确说明无法计算。

## 2. 证据层

| 标签 | 内容 | 约束 |
|---|---|---|
| `券商事实` | 订单/成交 ID、时间、方向、数量、状态、成交价、费用、币种 | 订单不等于成交；不得改写 |
| `事件事实` | 财报事件 ID、发布时间、所属财季、盘前/盘后、来源 | 财季来自事件/财报源，不来自订单日期猜测 |
| `用户事前输入` | 我的判断、市场相信什么、计划动作、失效条件、概率、计划风险 | 保留版本时间；事后补录单独标记 |
| `派生指标` | P&L、R、MAE/MFE、敞口、相对基准、执行偏差 | 记录公式、窗口、基准和缺失字段 |
| `Agent 推断` | 决策评价、可能归因、改进假设 | 使用置信度，不冒充事实 |

最小案例字段：

```text
case_id
symbol
earnings_event_id
earnings_fiscal_period
event_at + timezone + session
selected_order_ids[]
selected_execution_ids[]
review_window
user_thesis_version + authored_at
market_belief_version + authored_at
planned_actions_version + authored_at
invalidation_version + authored_at
primary_outcome_definition
benchmark
data_as_of
```

## 3. 完整性检查

在计算前给出简短表格：

| 检查 | 状态 | 影响 |
|---|---|---|
| 历史订单分页完整 | 完整/部分/失败 | 是否可宣称覆盖全部交易 |
| 订单与成交关联 | 完整/部分 | 是否可重建真实执行 |
| 财报事件匹配 | 已确认/候选/缺失 | 是否能归入财季 |
| 事前版本时间 | 事件前/事后补录/缺失 | 是否可评价计划遵守 |
| 费用与 FX | 完整/估算/缺失 | 净收益可信度 |
| 路径行情 | 完整/日线/缺失 | MAE/MFE 精度 |
| 账户净值与持仓快照 | 完整/部分/缺失 | 峰值敞口和仓位风险 |

若订单同步失败，不得用当前持仓反推历史成交；输出同步失败原因、已覆盖区间和可恢复步骤即可。

## 4. 输出结构

按以下顺序输出，省略没有证据的指标而不是填零：

1. **结论**：决策质量、执行质量、结果质量各一句；注明复盘模式与数据覆盖。
2. **自动关联**：事件、财季、所选订单/成交、复盘窗口、冲突或待确认项。
3. **用户事前记录**：原意呈现四个用户字段，并显示版本时间；事后补录显式标记。
4. **动作时间线**：计划、订单、成交、失效触发、风险调整、结果观察点。
5. **评分卡**：只放可计算指标，附公式/口径短注。
6. **决策与结果分离**：说明当时是否合理、执行是否一致、结果受哪些因素影响。
7. **继续 / 验证 / 规避**：每项必须指向证据或未知项。
8. **候选规则**：假设、适用条件、动作、失效、主指标、窗口、样本状态和下一次 review 条件。

季度或跨季度报告额外加入：样本漏斗、等权与资金加权结果、按市场环境/策略类型的分层、留出集结果、最大失败簇，以及规则状态变更建议。不要输出自动提升结论。
