# 财报交易复盘

## 坚持证据边界

- 先关联订单与成交，再创建或分析复盘案例。只使用用户选中的记录；不要把同标的附近的所有交易自动归因于财报。
- 把订单时间、方向、数量、状态、成交价和费用作为券商事实。把财报发布时间、财报所属季度和盘前/盘后属性作为事件日历事实；订单本身不能证明财报季度。
- 若事件日历缺失或冲突，列出候选事件并要求确认。不要用最近日期静默补齐。
- 将证据逐项标为 `券商事实`、`事件事实`、`用户事前输入`、`派生指标` 或 `Agent 推断`。保留来源、时区、币种和获取时间。
- 将用户填写的“我的判断”“市场相信什么”“计划动作”“失效条件”原意保留并按版本锁定。事件发生后补写的内容标为 `事后补录`，不得用于计算计划遵守度。
- 不暴露账户号、凭证或不必要的原始个人数据；保持只读，不提交、修改或取消订单。

## 选择复盘模式

1. **单事件复盘**：以 `标的 × 财报事件 × 决策包` 为一个样本，重建该事件前后被选中的订单和成交。
2. **所选案例组合复盘**：只分析用户本轮明确勾选的案例，以及每个案例已经确认关联的订单与成交。允许跨标的、跨公司财季；不得把同期间账户中的其他订单自动纳入。
3. **完整财报季 cohort**：只有在用户明确指定财报事件日期窗口和纳入规则时使用。按 `eventAt` 而不是不同公司的 `FYxxxx Qx` 标签圈定案例，并披露未关联订单、未建案例和未交易信号造成的覆盖缺口。
4. **跨季度规则验证**：冻结规则、主要指标、观察窗口和排除条件，再比较发现集与留出集；不要用同一批样本反复改规则又声称验证成功。

如用户没有指定模式：一个案例用单事件模式；两个以上明确选择的案例用所选案例组合复盘。不要仅因多个案例拥有相同 `fiscalQuarter` 字符串就声称覆盖了完整财报季；只有显式日期 cohort 才能称为完整财报季。

## 执行复盘流程

### 1. 做数据健康检查

检查历史同步区间、分页是否完整、订单/成交去重、时区、币种、费用与 FX、价格复权口径、财报事件来源、持仓和净值快照覆盖。明确区分：

- `可计算`：证据足以计算并有稳定定义；
- `部分可计算`：缺少费用、盘中路径或账户快照等字段；
- `不可计算`：缺少计划风险、基准、事件元数据或成交记录。

连接器超时或返回失败时，只记录一次限制并继续处理已有证据；不要把计划订单当作成交，也不要循环重试同一个请求。

### 2. 固定样本与事前版本

- 记录案例 ID、标的、事件 ID、财报所属期、事件时间、所选订单/成交 ID、复盘窗口和纳入理由；组合复盘同时记录用户勾选的案例 ID 集合。
- 将多笔加减仓、保护、平仓和反向操作按时间排序；同时保留订单意图与实际成交的差异。
- 选择唯一的主要结果窗口，例如“财报后第 5 个完整交易日收盘”。其他窗口只能作为敏感性分析。
- 在看结果之前固定胜负定义、基准、计划风险和排除条件。若这些字段原本不存在，保留为空并将本次分析标为探索性。

完整证据字段与输出标签见 [evidence-and-output.md](references/evidence-and-output.md)。

### 3. 重建决策而非只看盈亏

按时间线回答：当时可知什么、用户计划做什么、实际做了什么、首次触发失效发生在何时、何时降低风险或离场。分别评价：

- **事前决策质量**：判断、市场预期、催化路径、赔率估计、仓位和保护是否在当时信息下自洽；
- **执行质量**：入场、加减仓、成交、失效响应和风险预算是否符合事前计划；
- **结果质量**：实际盈亏、路径、相对表现与尾部风险；
- **归因可信度**：结果来自判断、执行、市场 beta、事件跳空、波动率/期限、运气，还是证据不足。

盈利不自动证明决策正确，亏损也不自动证明决策错误。对无法从数据识别的因果关系使用概率语言。

当复盘需要 Stage、市场当前相信什么或预期差判断时，联合使用 `analyze-market-narratives`。仅当价格结构与执行时点确实影响结论时再使用 `analyze-technical-structure`；EMA、Fib 和任何单一指标都不是强制框架。

### 4. 计算一致指标

读取 [metrics-and-validation.md](references/metrics-and-validation.md)，先报告覆盖率和缺失原因，再计算可用指标。至少考虑：

- 净 `R`、胜率、平均/中位盈利 `R`、平均/中位亏损 `R`、赔率、期望、Profit Factor；
- MAE、MFE、收益捕获率和尾部亏损；
- 计划动作遵守度、计划风险与实际风险偏差、失效响应延迟；
- 事件窗口内峰值总敞口/净敞口、集中度、保护贡献；
- 相对预先选定基准的超额结果与可定义的机会成本；
- 若事前保存了情景概率，再计算概率校准，不得事后补概率。

没有事前计划风险时不要事后伪造 `R` 分母；改报货币/P&L 与百分比结果，并把 `R` 标为不可计算。

### 5. 形成规则但不直接升级

将每条发现写成可证伪规则：适用条件、动作、失效、主要指标、观察窗口、排除条件、预期机制和可能失败的市场环境。按以下状态推进：

`候选 → 已登记测试 → 待人工 review → 试行 → 已验证`

- 单个案例只能生成候选假设，不能证明规则。
- 任何自动指标都只能提出状态变更建议；由用户人工 review 后才能提升。
- 达到样本下限也不等于有效。必须同时检查净期望、置信区间/不确定性、尾部损失、费用、相关样本、不同市场环境和留出集表现。
- 规则表现恶化、失效条件不可执行、或证据口径漂移时，降级或退役并保留审计记录。

### 6. 输出可操作复盘

遵循 [evidence-and-output.md](references/evidence-and-output.md) 的短报告结构，先给结论，再给证据。结尾只保留三类动作：

1. **继续**：证据支持且应保持的做法；
2. **验证**：下一财报季需预先登记的假设、指标和样本；
3. **规避**：已出现明确失败机制或违反风险边界的动作。

不要把探索性观察写成确定规则，不要为填满模板而制造指标。
