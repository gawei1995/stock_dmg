# 交易驾驶舱 · Trading Cockpit

把个人 TradingView 看盘界面、长桥 / IBKR 真实账户和一个持久 Codex Agent 放在同一桌面窗口；从研究判断、风险计划走到订单复盘与后续验证。系统是只读决策支持，不代替用户下单。

## 使用路径

### 看盘与账户

- 中间是完整 TradingView 网页的独立本机会话，不是官方 Widget 或应用自绘图表。保留个人布局、画线与指标；不共享 Chrome / TV Desktop 登录，也不读取或注入个人图表 DOM。
- 左侧共用持仓表，可切换长桥、IBKR 或全部账户。默认 USD 展示，保留币种和报价时点；跨券商购买力不能互抵。
- 右侧是单一 Codex App Server：对话、Skills / MCP / Apps、流式输出、取消和结果回收使用同一条链路。左右栏可以收起、分隔线可以调整。
- IBKR 账户 / 期权信息属于有条件支持；历史订单、EOD 以及确定性计仓尚未接入长桥同一闭环，不能把合并显示当作统一执行风控。见 [IBKR 设置](desktop/IBKR_SETUP.md)。

### 自由研究与持仓分析

- “自由研究”无需先连接券商，不自动附加账户快照或行情。持仓、候选买入和全组合分析分别校验必要证据。
- 完整工具核验失败时，可显式新建“受限研究对话”：独立隔离核验通过后，外部 MCP / Apps 关闭；本地 Skills 及原配置允许的其他研究能力保留。它不是放宽只读防护，也不是修复所有外部服务。
- 技术方法开放，EMA 3/5/8/13/21/144/169、Fib、AVWAP、相对强弱和成本分布代理按适用性采用，不能机械强制为主框架。OHLCV 成本代理不是真实逐笔筹码。
- 仓位、汇率、技术指标等确定性运算由宿主负责，并保留单位、分母、时间和来源；LLM 解释证据、处理冲突并提出条件方案。这不代表所有模型正文数字或外部事实已核验。未知不补零，模型建议不等于宿主接受值。
- 候选计仓受新鲜快照、估值、购买力、集中度和风险预算等约束；毛暴露 120% 预警、150% 硬上限。保存的计划是静态快照，不后台监控或执行。

### 连续研究主线（0.24.13）

进入“研究 / 复盘 → 研究主线”：

1. 写一句目前的判断，未持仓标的或主题也可建档。
2. 点击“新对话研究并生成草案”，在独立持久对话中整理市场预期、预期差、反证和下一验证点。
3. 编辑并勾选要采用的字段和来源，再明确确认；空字段和 AI 来源默认不采纳，旧判断版本保留。
4. 追加观察、设置下次检查日期；这些操作不会后台启动 Agent 或自动升级 Stage。
5. 明确关联已有真实订单复盘周期，冻结关联时的研究版本，不用后来的改写替代原判断。

记录保存时间不等于来源实际抓取时间；来源建议即使被采用仍可能未独立核验。研究补充材料不会进入盲态复盘，也不替代封存事前基线或赋予正式评分资格。

### 复盘与验证

- 订单区间、催化剂、持仓生命周期和自然月组合共用“复盘周期”。默认轻量事后复盘；需要验证事前判断时才进入封存、盲态 / 结果两阶段。
- 真实成交和已成交 / 部分成交父订单是主证据；未成交、纯撤单或不可核验记录只保留排除审计。框选 Buy→Sell 决定区间，长区间按连续 3 个交易日分段，不向前另找历史首笔。
- 重选订单会更新证据版本，旧分析保留但失效；首次阶段分析建立独立对话，后续追问继续原对话。
- 验证中心采用“AI 草案 → 用户确认观察 → 后续复盘候选 → 用户确认纳入 → 指标汇总 → 人工 Review”。样本数不等于独立性或统计有效性；正式规则晋级仍受门禁限制。
- 长桥组合快照只在应用运行 / 已显式启用后台、授权和捕获条件满足时采集。成功后不被被动盘后波动覆盖，退出 / 休眠 / 离线可能形成缺口，不补造历史。收盘重估数量与现金来自盘后观测，固定 `partial`，不是正式收益端点。
- 加密恢复包不含登录凭证、TV 登录状态或 Codex 外部完整对话；依赖原本机安全存储身份，不是跨设备灾备。

## 不变的边界

- 所有券商只读；禁止提交、修改、撤销订单、行权和转账，最终交易由用户在券商端完成。
- 只使用个人原生 TV 视图和一个 Codex harness；不重建 CLI/PTY、第二套工具监控或网页原型产品线。
- 长桥桥接使用官方全球 `.com/v2`；不静默回退到 `.cn` / 香港节点。不得关闭证书校验或修改全局代理来掩盖连接问题。
- Agent 的系统代理沿用原生进程级 `respect_system_proxy`，保留实验性说明与应用内退出选项；保存后下次应用启动生效，不中断分析。
- 保留账户数据、历史、授权、用户 Skills 与既有工作区改动。验证默认用隔离合成数据，真实账户 / 模型检查与安装替换需有明确范围。
- 不含 Developer ID 签名 / Apple 公证；不承诺零缺陷、每日必有快照或所有数据实时可用。

## 开发快速开始

环境：macOS、Node.js `>=22.13.0`。以下从仓库根目录运行：

```bash
npm --prefix desktop ci
npm run desktop:test
npm run desktop:dev
```

`desktop:dev` 会启动实际应用，可能读取默认应用 profile 和连接已配置服务；不要将它用作隔离测试命令，也不要让它与安装版同时写同一 profile。

本批改动齐备后统一运行 `npm test` 和 `npm --prefix desktop run audit:production`。安全审计有漏洞、无法连接或报告不完整均不能通过新的发布门禁。整批完成、允许冻结发布后才运行：

```bash
npm run verify:release -- --target mac
```

这个命令会测试、启动隔离界面并生成 DMG / ZIP，不是普通检查命令；不得每修一项就执行。禁止用新源码覆盖已验证的同版本产物，不自动安装。

## 新对话怎样继续

在 Codex 中选择同一 `stock_agent` 项目 / 本地目录，新建对话，让它先读 `AGENTS.md`、本 README 和 `NEXT_STEPS.md`。项目文件可以交接；不要假设新对话会自动继承本聊天全文、当前安装状态或外部授权。

官方说明 Codex 会从项目目录发现 `AGENTS.md` 指令；README / 待办需要通过这些指令或用户提示明确读取。见 [OpenAI Docs：AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

本仓库没有为新会话修改全局 Codex 设置。建议一条开发对话负责一个有边界的批次，每次结束更新 `NEXT_STEPS.md`，而不是不断延长一条聊天或重复粘贴全部历史。
